# Solana Ecosystem Report

An auto-updating report + interactive dashboard on the current state of the
Solana network: performance, validators, economics, and ecosystem growth —
pulled live via **direct RPC calls and keyless public APIs, with zero API
keys and zero third-party Python dependencies.**

**Live demo:** deploy to GitHub Pages (instructions below) — the workflow in
this repo does it automatically on every scheduled run.
**Sample output:** see [`/samples`](./samples) for a JSON, Markdown, and HTML
dashboard generated by this exact pipeline (using a mocked snapshot so the
samples are stable to review — see "About the samples" below).

---

## What it does

Every run, the pipeline:

1. Calls the Solana public RPC endpoint directly (`getSlot`, `getEpochInfo`,
   `getRecentPerformanceSamples`, `getVoteAccounts`, `getHealth`, `getSupply`,
   `getBalance`, `getSignaturesForAddress`, and `getBlock` for real fee data).
2. Calls DeFiLlama (TVL, DEX volume, stablecoin supply) and CoinGecko (SOL
   price) — both keyless public endpoints.
3. Derives clean metrics: TPS, slot time, epoch progress, validator
   delinquency, stake distribution, median transaction fee, an estimated
   Real Economic Value (REV) per block, TVL/price changes, and more.
4. Runs rule-based anomaly detection against a rolling history of its own
   past snapshots.
5. Writes three synchronized outputs from the same data:
   - `data/latest_report.json` — machine-readable
   - `data/latest_report.md` — human-readable
   - `docs/index.html` — a dark-theme interactive dashboard (self-contained,
     no CDN, works offline)
6. Appends the snapshot to `data/history.jsonl` for trend charts and the next
   run's anomaly baseline.

A GitHub Actions workflow (`.github/workflows/update-report.yml`) runs this
on a schedule, commits the refreshed files, and deploys `docs/` to GitHub
Pages — so once it's set up, it runs itself.

> **Note:** `data/` and `docs/index.html` ship pre-seeded with the same
> mocked sample described below, so the dashboard isn't blank on first
> clone. Running `python main.py --once` with real internet access
> immediately overwrites them with a live snapshot.

## Quick start

```bash
git clone <your-fork-url>
cd solana-ecosystem-report
python main.py --once        # generate one report right now
open docs/index.html         # view the dashboard (or just double-click it)
```

That's it — no `pip install`, no `.env` file, no signup. Requires Python 3.8+.

To keep it refreshing locally instead of via CI:

```bash
python main.py --loop --interval 900   # regenerate every 15 minutes
```

### Setting up the live, hosted version (recommended for judging)

1. Push this repo to GitHub.
2. In **Settings → Pages**, set the source to **GitHub Actions**.
3. In **Settings → Actions → General**, under "Workflow permissions," select
   **"Read and write permissions"** (the workflow needs to commit refreshed
   data back to the repo).
4. Either wait for the next scheduled run (every 30 minutes) or trigger it
   manually from the **Actions** tab (`Update Solana Ecosystem Report` →
   `Run workflow`).
5. Your dashboard will be live at `https://<you>.github.io/<repo>/`.

## Data sources and how they're integrated

| Source | What it provides | Auth needed |
|---|---|---|
| Solana public RPC (`api.mainnet-beta.solana.com`) | Slot, epoch, performance samples, validator/vote accounts, health, supply, block/fee data | None |
| [DeFiLlama](https://defillama.com) | Solana TVL history, DEX volume, stablecoin supply | None |
| [CoinGecko](https://www.coingecko.com) | SOL spot price, market cap, 24h volume/change | None |

Every network call goes through `src/http_client.py`, which wraps Python's
built-in `urllib` — there is no `requests` dependency, no SDK, and nothing to
authenticate. If you have a private RPC provider (Helius, Triton, etc.) for
higher rate limits, set `SOLANA_RPC_URL` as an environment variable and it's
used automatically.

**Solana ecosystem website scraping (`solana.com/data`) was deliberately left
out** rather than done unreliably: that page renders client-side and would
require a headless browser (a heavy, fragile dependency) to scrape. Where
it matters, this pipeline gets the same underlying numbers from DeFiLlama /
CoinGecko / RPC instead. If you want the scrape anyway, `src/external_sources.py`
is the place to add it — see "Extending" below.

### Twitter / X integration

Not wired up by default. The current X API requires a **paid** bearer token,
which would break this project's "no API keys" goal for anyone who doesn't
already have one. If you have a token, add a `TWITTER_BEARER_TOKEN` env var
and a `get_recent_announcements()` function to `src/external_sources.py`
following the same pattern as the DeFiLlama/CoinGecko functions, then fold
its output into `report_builder.py`.

### Ecosystem growth data gaps

Two requested metrics — **tokenized real-world-asset (equities) volume** and
**daily active addresses** — don't have a canonical keyless public feed as of
this writing. The report is explicit about this gap (see the "Ecosystem
growth" section of every output) rather than fabricating a number. The
bounty brief points at Dune Analytics dashboards for exactly this kind of
metric; if you have a Dune API key, `metrics.ecosystem_growth()` is where to
plug in a `dune-client` call against the specific dashboard you want to
track.

### Upcoming developments (Alpenglow, SIMDs, etc.)

There's no single keyless feed for Solana Improvement Document status
either, so this section (`src/config.py` → `UPCOMING_DEVELOPMENTS`) is a
short, manually curated list. It's deliberately structured as data, not
prose, so updating it is a one-line edit per item rather than a code change.

## Automation strategy

- **Trigger:** GitHub Actions `schedule` cron (`*/30 * * * *` by default —
  edit the cron line in `update-report.yml` to change the cadence; GitHub's
  minimum practical resolution is about 5 minutes).
- **Execution:** a fresh Ubuntu runner checks out the repo, runs
  `python main.py --once` (no build step, no dependency install needed),
  then commits `data/` and `docs/` back to `main` and deploys `docs/` to
  GitHub Pages.
- **Resilience:** every data source is wrapped so a single failing call
  (rate limit, timeout) degrades that one section to `null` with a logged
  reason in `source_errors`, instead of failing the whole run. You'll see
  this reflected in a "Sources unavailable this run" section in the
  Markdown/HTML output if it happens.
- **Local alternative:** `python main.py --loop --interval N` runs the same
  logic in a simple `while` loop with `time.sleep`, for anyone who'd rather
  run this on their own machine or server than use GitHub Actions.

## Anomaly detection

Implemented as explainable, rule-based checks (`src/anomaly_detector.py`) —
not a black-box model — so every flagged anomaly comes with the exact number
and rule that triggered it:

- **TPS deviation:** current average TPS vs. the rolling mean of the last 20
  snapshots this pipeline has collected; flags at ±30% deviation.
- **Slot time:** flags when average slot time exceeds 550ms (Solana's target
  is ~400ms).
- **Validator delinquency:** flags when delinquent validators exceed 5% of
  the total set.
- **TVL swings:** flags 24h TVL moves of 15% or more, in either direction.
- **SOL price swings:** flags 24h price moves of 10% or more.

Severity (`info` / `warning` / `critical`) scales with how far past the
threshold a metric is. All thresholds live in `src/config.py` under
`ANOMALY_THRESHOLDS` — change a number, no code changes needed.

## Median fee & REV methodology

Rather than assume Solana's flat 5,000-lamport base fee, the pipeline
samples one recent, finalized block via `getBlock` and computes the actual
median and mean fee paid across every transaction in it (base + priority
fees). The estimated Real Economic Value (REV) per block is the sum of
those fees, converted to USD at the current SOL price. This intentionally
**excludes MEV/tips routed off-chain**, since no keyless public source can
see that — it's a floor on REV, not a full accounting of it. This
limitation is stated directly in the report's `fee_and_rev_detail` section
and its `note` field.

## Output formats

- **JSON** (`data/latest_report.json`) — flat, well-typed, ready to feed into
  another dashboard or alerting system.
- **Markdown** (`data/latest_report.md`) — renders cleanly on GitHub, in
  Notion, in Slack previews, etc.
- **HTML dashboard** (`docs/index.html`) — dark theme, server-rendered SVG
  sparklines for TPS/slot-time/price/TVL trends, an anomaly banner, a
  top-validators table, and a roadmap panel. No JavaScript framework, no
  CDN, no client-side fetch — open the file directly and it works, including
  offline.

All three are generated from the *same* `report` dict in one pipeline run,
so they can never drift out of sync with each other.

## About the samples

`/samples` contains a JSON, Markdown, and HTML report generated by this
exact codebase (same `metrics.py`, `anomaly_detector.py`,
`markdown_report.py`, and `dashboard.py`), fed a **realistic mocked
snapshot** shaped exactly like real RPC/API responses, plus a fabricated
30-snapshot history that intentionally triggers one anomaly (a TPS dip) so
the anomaly banner and severity styling are visible in the sample. This was
necessary because the sandbox this was built in has outbound network access
restricted to package registries only — it cannot reach
`api.mainnet-beta.solana.com`, DeFiLlama, or CoinGecko to produce a live
sample. Running `python main.py --once` from any machine with normal
internet access produces the real thing using the identical code path (see
`main.py` → `src/report_builder.py` for the exact call graph — nothing
differs between the sample generation script and the real pipeline except
which functions supply the raw input data).

## Project layout

```
main.py                      CLI entrypoint (--once / --loop)
src/
  config.py                  All tunables: RPC URL, thresholds, refresh interval
  http_client.py              stdlib-only HTTP + JSON-RPC helpers
  rpc_client.py               Every Solana RPC call the bounty asks for
  external_sources.py         DeFiLlama + CoinGecko calls
  metrics.py                  Raw payloads -> clean report metrics
  anomaly_detector.py          Rolling-baseline + threshold anomaly rules
  history_store.py            Flat-file (JSONL) snapshot history
  markdown_report.py           Markdown renderer
  dashboard.py                 HTML dashboard renderer
  report_builder.py            Orchestrates one end-to-end run
data/                         Generated: latest_report.json/.md, history.jsonl
docs/                         Generated: index.html (served by GitHub Pages)
samples/                      Static example outputs (see above)
.github/workflows/            Scheduled automation + Pages deploy
```

## Extending

- **New RPC metric:** add a function to `src/rpc_client.py`, wire it into
  `collect_onchain_snapshot()`, then derive whatever you need in
  `src/metrics.py`.
- **New off-chain source:** same pattern in `src/external_sources.py`.
- **New anomaly rule:** add a threshold to `config.ANOMALY_THRESHOLDS` and a
  check in `anomaly_detector.detect_anomalies()`.
- **Different refresh cadence:** edit the `cron` line in
  `.github/workflows/update-report.yml`, or pass `--interval` to
  `main.py --loop`.
